From SGD to Adam and beyond

The adaptive optimizer that quietly powers modern AI.

Almost every large model you've heard of — GPT, Llama, Claude, Stable Diffusion — was trained with Adam or one of its descendants. It's the most-used algorithm in deep learning. But why does it work so well? Let's start from zero and build it up visually, with no math gatekeeping.

m = smoothed gradient → "the direction"
v = smoothed squared gradient → "the terrain map"
update = η · m / ( √v + ε ) → "direction ÷ scale"
That's it. That's Adam.

The Story

A ball, a hill, and a problem.

Imagine you're blindfolded on a mountain. You want to find the lowest valley. You can only feel the slope under your feet. How do you get down?

1

Feel the slope

Take a step downhill. This is gradient descent — the simplest training algorithm ever. It works on smooth single hills.

2

But the mountain has a billion parameters

A neural network is a function with millions of weights. The "mountain" is in a million-dimensional space. You can't see it — you can only sample the slope at your current position.

3

And some slopes are gentle, others are cliffs

Different parameters have wildly different gradient sizes. One weight might need a step of 0.001; another in the same layer needs 0.000001. One step size can't serve them all.

The Setup
Adam's whole invention is: let every parameter pick its own step size, automatically. That's the one idea. Everything else is bookkeeping to make it stable.
Why Naive Methods Fail

Watch SGD struggle.

SGD — stochastic gradient descent — is the simplest possible optimizer: take a step in the direction of the current gradient, scaled by a single learning rate. Watch what happens on an "ill-conditioned" bowl.

Two optimizers on the same valley

Loss surface: a long, narrow valley (the y-axis is 100× steeper than the x-axis). Both optimizers start at the same red dot. SGD (orange) zig-zags back and forth across the steep wall while barely making progress along the valley floor. Adam (blue) — same start, same number of steps — threads straight to the bottom.

The disease: per-parameter scale

The gradient in y is huge; in x it's tiny. One learning rate makes y explode or x stall. You can't win — pick a small lr and SGD crawls along the valley; pick a large lr and it bounces off the walls.

Adam's cure: per-parameter normalization

Adam estimates the typical size of the gradient for each parameter separately (that's the v in the equation). It then divides the actual gradient by that size — making every parameter's update land at roughly the same scale, regardless of how steep its local slope is.

The Core Idea

Two running averages, working together.

Adam keeps a moving average of two things for every weight. Each runs with its own time horizon. Drag the sliders and watch how each average responds.

How m and v track the gradient stream

Synthetic gradient stream: noisy measurements of slope, alternating between big positive and big negative. m (blue) tracks the average direction; v (teal) tracks the average size. Bigger β = longer memory. β₁≈0.9 (10-step memory) reacts fast; β₂≈0.999 (1000-step memory) is much smoother. The mismatch is the whole point.
m

First moment — the "velocity"

An exponentially-weighted moving average of the gradient. Smooths out noise, gives the optimizer momentum. Time constant: roughly 1/(1-β₁) ≈ 10 steps at β₁=0.9.

v

Second moment — the "terrain map"

An exponentially-weighted moving average of the squared gradient. Tracks how big the gradient typically is. Time constant: roughly 1/(1-β₂) ≈ 1000 steps at β₂=0.999. Slow on purpose.

Key Insight
The two time constants differ by 100× on purpose: direction should react quickly (you want to follow a changing slope), but scale should react slowly (a single outlier gradient shouldn't make the optimizer suddenly take huge steps).
The Algorithm

Adam, line by line.

Here it is, in plain pseudocode. Every line has a job. Try editing it below — the playground runs your code in the browser.

Pseudocode (Kingma & Ba, 2014)

# Given: gradients g_t at each step t
m = 0; v = 0            # initialize both moments to zero

for t in 1, 2, ..., T:
    g = compute_gradient(loss, params)
    
    m = β₁ · m + (1 - β₁) · g           # first  moment: "what direction?"
    v = β₂ · v + (1 - β₂) · g²          # second moment: "how big?"
    
    m̂ = m / (1 - β₁ᵗ)                  # bias correction (m)
    v̂ = v / (1 - β₂ᵗ)                  # bias correction (v)
    
    params -= η · m̂ / (√v̂ + ε)        # the actual update
2

State per parameter

Just two numbers: m and v. That's why Adam is cheap to implement and runs everywhere. ~8 bytes per parameter extra.

η, β₁, β₂, ε

Four hyperparameters

η (learning rate), β₁ (momentum decay, ~0.9), β₂ (scale decay, ~0.999), ε (numerical safety, 1e-8). Defaults almost always work.

O(P)

Memory cost

Linear in parameter count. Same as SGD with momentum. No extra activations stored, no extra forward passes.

Practical Tuning

Defaults that actually work.

Most papers use Adam with the same four knobs. Here are the values that have survived a decade of replication.

HyperparameterDefaultRangeWhat it controls
η (learning rate) 3e-4 1e-5 → 1e-2 How big each step is. Most sensitive knob.
β₁ (momentum) 0.9 0.85 → 0.95 How much past gradients influence direction. ~10-step memory.
β₂ (scale) 0.999 0.99 → 0.9999 How long the per-parameter scale estimate averages over. ~1000-step memory.
ε (epsilon) 1e-8 1e-6 → 1e-8 Stability term in denominator. Almost never changed.
warmup steps ~5% of budget 100 → 10k Linear ramp from η/100 → η. Critical for transformers.
weight decay 0 (Adam) / 0.1 (AdamW) 0 → 0.1 Regularization. Use decoupled form (AdamW), not L2.

What to do when training blows up

⚠

Loss is NaN or spikes to infinity

The step was too big somewhere. Try in this order: (1) increase warmup, (2) lower peak lr by 3–10×, (3) clip gradients to norm 1.0, (4) check for bad data.

⚙

Loss plateaus early

Either lr is too small (try 2× larger), or the model has saturated. For transformers, also check β₂ — 0.95 can help with sharp minima.

✓

Loss decreases but val loss diverges

Classic overfitting. Add weight decay (AdamW form), or use a learning rate schedule that decays to ~10% of peak. Don't lower the lr too early — that just hides the overfitting.

i

Training is slow on a new model size

Wider models often want smaller lr. The classic "1/width" rule is rough — a sweep across 2–3 widths gives a fitted exponent you can extrapolate. But: only muP makes this rigorous.

Rule Of Thumb
If you have to change one thing, change the learning rate. Everything else is a fine-tune. lr sweeps are the single highest-ROI experiment in deep learning.
The Family

Adam has children. Here they are.

A decade of follow-ups. Each one tweaks the core idea for a specific problem.

2014
Adam the original
Kingma & Ba. Combines RMSProp (per-parameter scaling) with momentum (gradient direction smoothing). The default optimizer of deep learning.
2017
AMSGrad controversial
Fixed a theoretical convergence bug in Adam by taking max(v) over history. Worked in theory; in practice it often hurt convergence speed. Few papers use it.
2019
AdamW now the default
Loshchilov & Hutter. Decouples weight decay from the gradient — instead of L2 regularization (which interacts badly with adaptive scaling), apply decay directly to the weights. Critical for transformers.
2021
AdaFactor memory-efficient
Shazeer & Stern. Doesn't store a full v matrix per parameter — uses a factored approximation. Same convergence, ~4× less optimizer memory. Used in T5.
2022
Sophia second-order-ish
Liu et al. Uses an estimate of the Hessian diagonal (via cheap Gauss-Newton approximation) to scale updates. Pretrains language models ~2× faster than Adam. Adds a tunable hyperparameter.
2023
Lion sign of momentum
Chen et al. Replaces the per-element division with the sign of the momentum. Every parameter gets exactly +η or -η. Cheaper than Adam, often matches or beats it on transformers.
2024
Muon matrix-aware
Jordan et al. Optimizer specifically for matrices. Treats the weight matrix as a whole (Newton-Schulz orthogonalization) instead of element-wise. Shown to train a transformer 35% faster than AdamW. New default for some training stacks.
2024
Distributed Shampoo second-order
Anil et al. (Google). Approximates the full preconditioner (inverse Hessian) using tensor decomposition. Strong empirical results at scale. Expensive but worth it for very large models.

Where Things Stand

The frontier, 2024–2025.

The honest summary: Adam is no longer the unchallenged default, but its core idea — per-parameter scaling — has never been seriously disputed. The research is about how to scale, not whether.

↑

Scaling laws for optimizers (2024)

Recent work shows that optimizer choice matters more at scale than at small scale — the gap between AdamW and Lion grows with model size, while the gap between AdamW and SGD-with-momentum shrinks. Translation: papers comparing optimizers on tiny models should not be trusted.

★

Muon is the surprise of 2024

Keller Jordan's Muon — Newton-Schulz orthogonalization of momentum updates — trains a transformer to the same loss in 35% fewer steps than AdamW. Now the default for the hidden layers in some NanoGPT-style setups. The optimizer community has noticed.

⚙

The "no warmup" debate

2024 paper: with the right lr schedule, transformers train fine without warmup. Counter-paper: warmup is still needed when batch size changes mid-training. The honest answer: warmup costs nothing, removes a class of bugs. Use it.

⚡

Sign-of-gradient optimizers come back

Lion and the older signSGD are having a moment. The simple insight — every parameter gets the same step magnitude, just a + or − — works surprisingly well at scale. Memory cost is half of Adam.

∇

Second-order methods get cheap

Sophia and Distributed Shampoo have shown that approximate second-order methods can be made fast enough for large-scale training. The cost: more hyperparameters, more failure modes. Still not plug-and-play.

✗

Adam's known weak spots

(1) Edge of stability: Adam can converge to regions where the loss curvature is sharper than the optimizer expects. (2) Generalization gap: sometimes Adam-trained models generalize worse than SGD-trained ones (especially on small datasets with weight decay). (3) Bias correction never fully decays — the 1/(1-β₂ᵗ) term is still 1% off after 4,000 steps.

The honest take

Bottom Line
Adam's core idea — per-parameter adaptive scaling — is one of the most replicated findings in machine learning. The default settings (β₁=0.9, β₂=0.999, lr=3e-4) work for a remarkable range of problems. Newer optimizers (Lion, Muon, Sophia) win on specific benchmarks but haven't displaced Adam as the safe default. If you're starting a project today: AdamW with β₁=0.9, β₂=0.95, wd=0.1, lr=3e-4, 500-step linear warmup, cosine decay. You can swap in Muon or Sophia later if you have time to tune.
